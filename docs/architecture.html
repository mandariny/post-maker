여행 블로그 자동화 MVP 아키텍처

현재 프로젝트는 Spring Boot 백엔드 없이 React 프론트엔드와 Supabase Auth, Database, Storage, Edge Functions를 중심으로 구성되어 있다. OpenAI API와 Kakao Local API는 브라우저에서 직접 호출하지 않고 Supabase Edge Functions 뒤에 둔다.

1. 전체 구성

Frontend

ReactTypeScriptViteTailwind CSS

  • 사용자 로그인 상태 표시
  • 여행 기록 생성 및 선택
  • 사진 업로드 및 브라우저 EXIF 추출
  • 장소 선택, 메모 입력, 초안 수정/복사

Supabase

AuthPostgresStorageEdge Functions

  • Google OAuth 인증
  • 여행/사진/장소/초안 데이터 저장
  • 여행 사진 파일 저장
  • 외부 API 키를 서버리스 함수에서 보호

External APIs

Kakao Local APIOpenAI API

  • GPS 좌표 기반 주변 장소명 또는 주소 추정
  • 선택된 장소와 사용자 메모 기반 Markdown 초안 생성

Deployment

Static FrontendDockerCI

  • 프론트엔드는 정적 빌드로 배포 가능
  • Supabase 함수와 마이그레이션은 별도 배포
  • CI는 프론트 테스트/빌드와 Docker build 수행

4. 사용자 흐름

1. 로그인

React 앱이 Supabase Auth의 Google OAuth를 시작한다.

2. 여행 생성

trips에 사용자 소유 여행 기록을 생성한다.

3. 사진 업로드

브라우저에서 EXIF를 추출하고 trip-photos에 저장한다.

4. 장소 추정

GPS가 있으면 guess-place 함수가 Kakao Local API를 호출한다.

5. 그룹화

촬영 날짜와 장소명 기준으로 place_groups를 재생성한다.

6. 장소 선택

사용자가 포함할 장소를 선택하고 장소별 메모를 입력한다.

7. 초안 생성

generate-blog-draft 함수가 OpenAI API를 호출한다.

8. 저장/복사

Markdown 초안을 blog_drafts에 저장하고 화면에서 복사한다.

5. 보안 경계

  • 브라우저에는 Supabase URL과 publishable key만 노출한다.
  • OPENAI_API_KEY, KAKAO_REST_API_KEY는 Supabase Edge Function secrets에만 둔다.
  • 모든 사용자 데이터 테이블은 RLS를 켜고 auth.uid() = user_id 정책으로 제한한다.
  • Storage 경로는 {user_id}/{trip_id}/{file} 구조를 사용하고, 첫 번째 폴더가 로그인 사용자와 일치해야 접근 가능하다.
  • service_role 또는 secret key는 프론트엔드 env에 넣지 않는다.

6. 배포와 설정

  1. Supabase Auth에서 Google provider를 활성화한다.
  2. Supabase Auth redirect URL에 http://localhost:5173 및 운영 URL을 추가한다.
  3. supabase db push로 마이그레이션을 적용한다.
  4. guess-place, generate-blog-draft Edge Functions를 배포한다.
  5. Edge Function secrets로 OPENAI_API_KEY, OPENAI_MODEL, KAKAO_REST_API_KEY를 설정한다.
  6. 프론트엔드에는 VITE_SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY를 설정한다.
